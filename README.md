# OpEndSkipper

OpEndSkipper — Chromium-розширення для Chrome 119+ на Manifest V3, яке
пропускає задану кількість секунд на початку та наприкінці HTML5-відео.

## Профілі за URL

Налаштування зберігаються окремо для ключа, отриманого з повного URL верхньої
сторінки вкладки після застосування глобальних URL-фіксерів. Наприклад,
`/show-a` і `/show-b` можуть мати незалежні профілі. Новий ключ завжди починає
зі значень:

```js
{
  enabled: false,
  skipStart: 0,
  skipEnd: 0
}
```

Саме відкриття сторінки не створює запис у storage. Профіль з'являється лише
після збереження або явного перемикання стану в popup. Старі глобальні
налаштування видаляються та не успадковуються URL-профілями.

Popup дозволяє скопіювати лише `skipStart` і `skipEnd` та вставити їх у профіль
іншого URL. Тимчасовий буфер `copiedSkipSettings` зберігається у
`chrome.storage.local`, не синхронізується та не містить URL або `enabled`.
Під час вставлення стан `enabled` цільового профілю зберігається.

Кожний ключ профілю зберігається в окремому елементі `chrome.storage.sync`.
Storage-ключ має префікс `profile:v1:` і SHA-256 ключа профілю; значення містить
сам ключ і профіль. Так окремий великий об'єкт не впирається в ліміт приблизно
8 КБ на один sync-елемент. Загальні квоти `chrome.storage.sync` все одно
обмежують кількість і сумарний розмір профілів.

## URL-фіксери

URL-фіксери — глобальні синхронізовані правила, які послідовно, зверху вниз,
перетворюють URL верхньої сторінки на ключ профілю. Вимкнені правила
пропускаються, а порядок можна змінювати кнопками зі стрілками.

Після першої ініціалізації створюється звичайне редаговане правило
«Відкинути все після `#`». Наприклад:

```text
https://example.com/player.html#t:509-s:1-e:56
→ https://example.com/player.html
```

Підтримуються буквальні операції відкидання після першого або останнього
входження, а також видалення та заміни точного тексту на початку, в кінці або
всюди. Наприклад, «Відкинути все після останнього входження» зі значенням `/`
перетворює `https://example.com/a/b/c` на `https://example.com/a/b`, не
пошкоджуючи протокол. Регулярні вирази не підтримуються.
Правила можна вимикати, редагувати, видаляти та переставляти; порожній список
є допустимим і не спричиняє повторного створення початкового правила.

Зміна правил може негайно переключити активний профіль. Дані зі старого ключа
не копіюються і не об'єднуються автоматично. Збережені раніше профілі з
hash-фрагментами залишаються у storage та знову стануть доступними, якщо їхній
ключ знову буде сформовано правилами.

## Відео в iframe

Content script запускається з `all_frames: true`. Кожний фрейм запитує профіль
у service worker, а той визначає URL верхньої сторінки через вкладку
`sender.tab.id`. Тому cross-origin iframe не читає `window.top.location` і
отримує ті самі налаштування, що й основна сторінка.

Після збереження service worker надсилає оновлений профіль усім content scripts
вкладки. Для кнопок «Поточний» і «Залишок» він збирає стан відео з усіх фреймів
і віддає popup активне або останнє активне відео.

Зміни URL відстежуються через `tabs.onUpdated`, події сторінки та
`webNavigation` для верхнього фрейму. Це охоплює звичайну навігацію,
`pushState`/`replaceState`, переходи назад/вперед і зміну hash у SPA без
постійного опитування вкладок.

## Встановлення

1. Відкрийте `chrome://extensions` у Chromium-браузері.
2. Увімкніть режим розробника.
3. Натисніть **Load unpacked / Завантажити розпаковане**.
4. Виберіть кореневу директорію цього репозиторію.
5. Для локальних `file://` сторінок окремо дозвольте розширенню доступ до URL
   файлів на сторінці керування розширенням.

## Ручна перевірка

- Новий URL показує `disabled`, `0`, `0` і не перемотує відео.
- Збережені значення застосовуються без перезавантаження.
- Два різні ключі після URL-фіксерів мають різні профілі.
- Початкове правило відкидає hash; URL без `#` не змінюється.
- Вимкнення, редагування, видалення та перестановка правил одразу змінюють
  прев'ю і завантажують профіль нового ключа.
- Видалене початкове правило не створюється повторно.
- Наявне під час завантаження та динамічно додане відео обробляються.
- Відео в cross-origin iframe використовує профіль верхньої сторінки.
- «Поточний» і «Залишок» знаходять активне відео також усередині iframe.
- «Копіювати» бере незбережені значення часових полів, але не `enabled`.
- «Вставити» зберігає часові значення для нового URL, не змінюючи `enabled`.
- Пошкоджений або відсутній локальний буфер залишає «Вставити» неактивною.
- Один буфер можна повторно застосувати до кількох URL і після перезапуску popup.
- Після SPA-переходу popup і відео отримують профіль нового URL.
- Завершення відео відбувається штатно після одноразового пропуску кінцівки.
