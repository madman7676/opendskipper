# OpEndSkipper

OpEndSkipper — розширення для Chromium на Manifest V3, яке автоматично пропускає задані частини HTML5-відео, зокрема у frames/iframes. Воно має Easy та Advanced режими; налаштування прив'язані до нормалізованого URL верхньої сторінки.

## Профіль, режим і Enabled

Ключ профілю (`titleId` / `profileKey`) утворюється з URL верхньої сторінки після URL-фіксерів. Різні ключі мають окремі налаштування. Новий Easy-профіль має `enabled: false`, `skipStart: 0` і `skipEnd: 0`; саме відкриття сторінки не записує його у storage. Початковий режим — Easy.

Перемикач **Увімкнено** у шапці popup керує обома режимами поточного профілю:

```text
Enabled = false           → пропуски не виконуються
Enabled = true + Easy     → виконуються Easy-пропуски
Enabled = true + Advanced → виконуються діапазони поточного Episode ID
```

Easy-часи та Advanced-дані зберігаються окремо й не видаляються при перемиканні режиму. Якщо чернетка Advanced має незбережені зміни, popup просить підтвердити її скасування перед перемиканням.

## Easy Mode

- **Початок** (`skipStart`) — перехід із початкового інтервалу `[0, skipStart)` до його кінця після готовності відео. Якщо відтворення вже пройшло цей інтервал, перемотування назад немає.
- **Кінець** (`skipEnd`) — під час відтворення перехід з останніх `skipEnd` секунд до кінця відео. Потрібна відома скінченна тривалість. Перехід зупиняється трохи перед кінцем, щоб відео завершилося штатно.

Поля — нативні `type="time"` з окремим індикатором дробової частини. Значення профілю та media time залишаються числами в секундах, тому дробові секунди зберігаються. **Поточний** бере `currentTime` активного відео для початкового пропуску, **Залишок** бере `duration - currentTime` для кінцевого. Ручне редагування нативного поля задає цілі секунди й скидає дробову частину. Після змін натисніть **Зберегти для цього URL**.

**Копіювати** бере поточні значення часових полів, навіть незбережені. **Вставити** записує їх у профіль іншого ключа, зберігаючи його `Enabled`. Easy-пропуски використовують той самий `RangeExecutor`, що й Advanced.

## Advanced Mode

Advanced задає довільний набір інтервалів `[start, end]` для поточного `episodeId`. Інтервали можна додавати, редагувати й видаляти. Редактор приймає час вручну або з активного відео. Розгортані **Шаблони** пропонують `0 → поточний`, `0 → 1:30`, `поточний → +1:30` і `поточний → кінець`.

**Зберегти у чернетку** змінює лише локальний набір у popup. **Скасувати** в редакторі закриває його без застосування полів. Видалення рядка й **Вставити набір** теж змінюють лише чернетку. **Зберегти набір** записує всі її діапазони для поточного Episode ID; **Скасувати набір** повертає останній збережений набір. **Копіювати набір** копіює саме збережений набір.

При збереженні межі нормалізуються до 10 мс (`Math.round(seconds * 100) / 100`). Пара нормалізованих меж утворює timing key. Глобальний локальний pool повторно використовує однакові timing records між епізодами й профілями; створений record не редагується. Редагування діапазону створює або знаходить інший key і переприв'язує лише поточний епізод. Видалення прибирає його посилання, не стираючи record з pool.

```text
episodeId → timing keys → global timing pool → RangeExecutor → Time.seekTo()
```

## Episode Detector

`profileKey` і `episodeId` — різні ідентичності. Перший визначає профіль, другий — набір Advanced-діапазонів усередині нього:

```text
raw top-level URL → URL Fixers → normalized profileKey
raw top-level URL або обраний Player URL source → detector transforms → episodeId
```

Автоматичний Episode Detector налаштовується окремо для профілю. **Top-level URL** використовує сирий URL верхньої сторінки без URL-фіксерів. **Player URL** використовує один вибраний *тип* джерела з кандидатів, які збирають content scripts у фреймах:

- URL документа фрейму (`frame-url`, за наявності відео);
- `iframe.src` (`iframe-src`);
- `video.currentSrc` (`video-current-src`);
- `video.src` (`video-src`);
- `<source src>` усередині відео (`source-src`).

Service worker збирає кандидатів з фреймів і впорядковує їх за станом відтворення та frame ID; detector бере перший кандидат **обраного типу**. Popup показує доступні кандидати, сире значення обраного джерела й preview результату після transforms. `episodeId` — довільний непорожній рядок після нормалізації пробілів, не обов'язково номер серії.

Коли визначений ID змінюється, service worker завантажує набір нового епізоду й оновлює content scripts. Якщо вибране джерело тимчасово недоступне, останній валідний ID зберігається в поточному контексті. Після зміни профілю або конфігурації detector контекст скидається; доки новий ID не визначено, Advanced не виконує пропуски. Player URL **не** перемикається мовчки на інший тип джерела.

## String transforms і URL-фіксери

Episode Detector має власний впорядкований ланцюжок transforms. Реалізовані буквальні операції: відкинути після першого або останнього входження (`truncateAfter`, `truncateAfterLast`), взяти після першого або останнього входження (`takeAfterFirst`, `takeAfterLast`), взяти останню непорожню частину за роздільником (`lastNonEmptyPart`), отримати query parameter (`queryParameter`), видалити або замінити точний текст (`removeExact`, `replaceExact`). Для видалення й заміни можна обрати початок, кінець або всі входження. Регулярні вирази не використовуються.

**URL-фіксери** — окремі глобальні правила лише для `profileKey` / `titleId`. Вони застосовуються до URL верхньої сторінки по черзі; правило можна додати, змінити, вимкнути, видалити або пересунути. Тут доступні тільки `truncateAfter`, `truncateAfterLast`, `removeExact` і `replaceExact`. Початкове редаговане правило відкидає фрагмент після `#`; порожній збережений список допустимий. Якщо результат правил не є придатним URL-ключем, використовується початковий URL і показується попередження. Зміна ключа підключає профіль нового ключа без автоматичного перенесення даних.

URL-фіксери не змінюють вхід Episode Detector. Обидві функції використовують спільні буквальні primitives з `string-transforms.js`, але мають окремі налаштування й різні набори доступних операцій.

## Виконання діапазонів

```text
active range → RangeExecutor.executeRange() → Time.seekTo() → video.currentTime
```

Час медіа зберігається як JavaScript `number` у секундах; дробові секунди підтримуються. `RangeExecutor` перевіряє межі й одноразовість виконання, а `Time.seekTo()` є єдиною низькорівневою точкою запису `video.currentTime`. У ній централізовані timing offset (у поточному runtime він вимкнений), обмеження цілі межами медіа та відступ 0,05 с від кінця. Перехід назад не виконується.

Оброблені діапазони відстежуються окремо для кожного `<video>`. Стан очищається під час повторного запуску після завершення, зміни source або подій нового завантаження медіа, а також при зміні профілю, `Enabled`, режиму, Episode ID чи активних налаштувань/діапазонів. Content script обробляє наявні та динамічно додані відео.

## Storage

| Сховище | Дані |
| --- | --- |
| `chrome.storage.sync` | Easy-профілі за hash нормалізованого ключа (`enabled`, `skipStart`, `skipEnd`) та глобальні правила URL-фіксерів. |
| `chrome.storage.local` | Окремий Advanced-профіль для кожного ключа: активний режим, конфігурація Episode Detector і посилання епізодів на timing keys; глобальний pool timings; типізований буфер копіювання Easy-часів або Advanced-набору; уподобання відкритості секцій Templates та Episode Detector. |

Поточний Episode ID визначається під час роботи для вкладки, а не зберігається як ручний вибір. Буфер копіювання спільний для обох режимів: копіювання одного типу замінює попередній вміст.

## Popup і взаємодія компонентів

Popup показує `Enabled`, перемикач Easy/Advanced і нормалізований ключ профілю. У Advanced є поточний Episode ID, розгортаний Episode Detector і розгортані Templates у редакторі; окрема панель URL-фіксерів показує вхідний URL і результат нормалізації. Результати й помилки показуються як toast.

Поки визначається контекст вкладки, loading overlay блокує popup; помилка завантаження URL завершує цей стан повідомленням. Якщо відео не знайдено, overlay блокує тільки налаштування пропусків, а `Enabled`, режим і URL-фіксери лишаються доступними. Popup періодично перевіряє появу відео й розблоковує поля.

```text
Popup ↔ Service Worker ↔ Content scripts у всіх доступних фреймах ↔ <video>

top-level URL → URL Fixers → profileKey → дані профілю
Episode Detector → episodeId → Advanced timing keys
profileKey + episodeId + mode + Enabled → active ranges → RangeExecutor → Time.seekTo()
```

Service worker визначає URL верхньої сторінки через `webNavigation` для вкладки, тому content script у cross-origin iframe не читає `window.top.location`. Worker збирає стан відео й кандидати Episode Detector з фреймів та розсилає оновлення профілю. Навігація вкладки, зміни URL у SPA, зміни storage і джерел медіа оновлюють runtime-контекст.

  popup.html / popup.css / popup.js   Інтерфейс, Easy, URL-фіксери, стан popup

  time-field.js                      Нативне поле часу й дробовий індикатор

  profiles.js                        Easy-профілі та Easy clipboard

  string-transforms.js               Буквальні операції над рядками
  episode-detector.js                Конфігурація, кандидати й визначення episodeId

## Локальна розробка

Build step немає: `manifest.json` посилається безпосередньо на файли репозиторію. У Chromium 119+ відкрийте `chrome://extensions`, увімкніть режим розробника, натисніть **Load unpacked / Завантажити розпаковане** й виберіть кореневу папку репозиторію, де лежить `manifest.json`. Для `file://` сторінок окремо дозвольте розширенню доступ до URL файлів.

Після зміни коду натисніть **Reload / Перезавантажити** на картці розширення. Уже відкриті сторінки можуть потребувати перезавантаження, щоб отримати нові content scripts; потім відкрийте popup знову.

## Тести

Тести використовують вбудований `node:test`, без пакета збірки або зовнішніх залежностей:

```sh
node tests/time.test.js
node tests/advanced.test.js
node tests/episode-detector.test.js
```

`time.test.js` перевіряє час, seek/range pipeline, Easy runtime, mode/Enabled, частину popup і повідомлень. `advanced.test.js` охоплює timing pool, storage, чернетку, шаблони й UI detector. `episode-detector.test.js` перевіряє URL-фіксери, transforms, candidates і переходи Episode ID. Тести запускають логіку та імітовані browser API/DOM у Node; вони не замінюють ручну перевірку у Chromium реальних відео, iframe, навігації та вигляду popup.

## Обмеження

- Нативне `type="time"` показує значення лише в межах однієї доби. Збережений час понад 23:59:59 лишається числом у секундах, але нативне поле не може відобразити його як час; підказка показує це обмеження.
- Player URL detector залежить від доступності й стабільності вибраного типу source. Відсутній source не замінюється іншим автоматично.
- Робота popup, повідомлень і content scripts у реальному браузері потребує Chromium; наявні Node-тести не автоматизують повну браузерну інтеграцію.
